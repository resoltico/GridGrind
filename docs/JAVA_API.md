# Java API

Build and execute Java integrations with the Eclipse Temurin 27 JDK pinned in
[container-runtime.properties](../release/container-runtime.properties). Build, development and
runtime use that same JDK; generated bytecode targets Java 26. Follow the
[development setup](DEVELOPER.md#toolchain-and-dependencies) for the exact environment.

Pure authoring lives in core.authoring. GridGrindPlan and the selector-first Targets, Values,
ExpectedValues, Tables and Links facades create the same canonical WorkbookPlan used by JSON.
They do not create a second execution engine or implicit authority. Generated step IDs use the first
unoccupied ID in their family across all existing steps. Explicit duplicate IDs fail when appended;
a rejected append leaves the builder and subsequent allocation unchanged.

The [compile-verified example](../examples/java-authoring-workflow.java) demonstrates typed
SheetName, RangeRef and TableName values, source-backed text, ordered operations and explicit
execution bindings. [Model vocabulary](../core/VOCABULARY.md) distinguishes authored specs,
patches, factual reports and source-bearing resolved values.

Execution belongs to engine.api. Obtain the request executor or doctor from GridGrindEngine
and supply host-owned GridGrindRequestInputs with an ExecutionGrant. Applications that only
author or serialize plans need core/json, without the workbook runtime. Execution adds engine.

Every `ExecutionGrant` includes an explicit `maxInputSnapshotBytes` allowance. Hosts select the
finite budget for their workload; `ExecutionGrant.denied()` has a zero-byte allowance. The host
working directory establishes the execution root for authored paths; exact stored filesystem
identities govern containment, grant matching and snapshot reuse. The separate scratch parent
contains private per-run directories. Finalization deletes those directories and preserves the host parent.

A `GridGrindPayloadOpener` binds standard input lazily. The engine checks authority before opening
it, snapshots the sequence once, and closes the transferred stream. Hosts that lend a process-owned
stream supply a non-closing wrapper. Byte-array inputs are checked against the allowance before
an owned copy is made. A doctor invocation and an execution have independent resource lifetimes.

`GridGrindJson.readRequest` and `analyzeRequest` borrow their InputStreams and leave them open.
Request reads enforce the 16 MiB document limit during acquisition with one overflow byte;
source payloads use the grant's separate aggregate allowance. `readGrant` strictly decodes the
whole authority document against the explicit host path root.

Optional fields use Optional and are omitted from JSON when absent. Wire scalar value records
serialize as JSON primitives, preserving identifier strings. Typed values validate their
authoring or observation contract; observed labels do not silently acquire authoring restrictions.

Concrete `CellAddress` values expose zero-based `rowIndex` and `columnIndex`; `RangeRef` exposes
ordered rectangle indices, row/column/cell counts and containment. String constructors parse A1
notation, and `value()` renders canonical A1 notation. Case, `$` markers and a repeated single-cell
endpoint do not distinguish concrete targets. Formula bodies and observed `RangeLabel` values
retain their separate contracts.

Observed `CellValue` text, numeric and error records are not writable operands. Execution consumes
`ResolvedCellWrite`: validated materialized text, finite authored numbers, stored errors, formulas,
rich text and temporal values, with shared blank and boolean leaves. Observations still report
empty text, nonfinite numbers and evaluation-only errors; exact authored numeric expectations
remain finite.

`CellValueSpec.Date` and `DateTime` carry timezone-free Gregorian civil values. The receiving
workbook's 1900/1904 calendar determines the lower bound; the upper bound is 9999-12-31.
`DateTime` rejects fractions finer than a millisecond. A `NEW` workbook uses the 1900 calendar.
Native admission checks the entire intrinsic temporal batch before mutation, rather than
publishing a sentinel or silently truncating authored precision.

[`CellTemporalReport`](../core/src/main/java/dev/erst/gridgrind/core/model/value/CellTemporalReport.java)
is a closed interpretation result: `NotTemporal`, `Interpreted(kind, isoValue)` or
`Unrepresentable(kind, reason)`. The VALUE facet remains the original number. Pattern-match the
result rather than treating a date-like format as proof that every stored serial is representable.
TEMPORAL can be requested independently; request VALUE when the original numeric fact is also needed.
Execution uses fixed en-US formatting and timezone-neutral civil semantics; caller JVM defaults
and existing POI thread-local settings are preserved. The published executor/doctor facades can be
shared; each invocation owns its native context, while callbacks remain on the caller thread.

Drawing reports retain native coordinate units. `DrawingCoordinateReport` distinguishes integer
EMU, lexical `Measured` values and VML `Pixels`; named width/height EMU fields keep their stated
unit. Pattern-match the coordinate instead of assuming every marker offset uses DrawingML units.
Chart and drawing titles use the closed `ChartReport.Title` forms, including an explicit absent title.

Chart reference caches report stored declarations and physical point order. Their optional counts,
indices, value text and per-point formats are not filled from live cells or padded into dense arrays.
`ChartReport.AxisCrossing` distinguishes an absent declaration, a stored mode and raw validated
numeric `valueText`, including native exponent and nonfinite spellings. See the
[cache](reference/numericCacheTypes.md), [axis](reference/axisCrossingTypes.md) and
[drawing coordinate](reference/drawingCoordinateReportTypes.md) contracts for exact fields.

Authored picture and preview payloads are checked against their declared format before native
mutation. Inline base64, file and standard-input payloads share the supported media profiles and
[media limits](LIMITATIONS.md#lim-042--authored-media-payload-bytes). These bounds cover payload
uses and expanded media work separately from the host's input-snapshot byte allowance. Each
authored occurrence charges even when it reuses a source snapshot. The format list comes from
[`PictureDataSpec`](reference/pictureDataSpecType.md); all formats use the engine's Java
structural readers, without external image tools or PostScript execution. Successful media
admission establishes the supported structural profile, not a visual rendering certification.

`GridGrindProtocolCatalog.lookupValueFor` returns `Optional<CatalogLookupValue>`. Exhaustive switches
handle `TypeEntry`, `NestedTypeGroup`, `PlainTypeGroup` and `TopLevelTypeGroup` directly. Note
resolution accepts that same typed result. The core also declares catalog field meanings and
qualified lookup namespaces used by discovery interfaces.

Read complete requests with `GridGrindJson.readRequest` or `analyzeRequest`, and host authority
with `GridGrindJson.readGrant` using an explicit path root. These APIs own request size, duplicate
handling, structural diagnosis and whole-document authority checks. The generic mappers in
`GridGrindJsonMapperSupport` support JSON trees, value fragments and writing documents; decoding
`WorkbookPlan` or `ExecutionGrant` through them is unsupported and directs callers to the owned
read API. Rebuilding a shared mapper retains that guard.

and [development](DEVELOPER.md) for the exact model and verification commands.
